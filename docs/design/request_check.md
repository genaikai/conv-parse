# 요구 확인(형식 · 언어 · 길이) — 측정과 결정

약한 모델(Qwen3.5-9B)을 실제로 붙여 보고 드러난 결함 하나와, 그것을 고치면서 세운
검증 방식을 기록한다. 결론부터: **판정자에게 증거를 요구하던 것을 코드가 확인하는
쪽으로 바꿨다.** 그리고 정규식을 우리 골든셋으로 재는 것은 아무것도 증명하지 않는다는
것을 실측으로 확인했다.

## 1. 증상 — 맞는 값이 지워진다

`--golden-set observations` 을 Qwen3.5-9B 로 돌렸더니 관측 필드 일치가 79/102 였다.
무너진 자리가 한쪽으로 몰려 있었다.

| 필드 | 일치 |
|---|---|
| `complaint_target` | 21/21 |
| `question_domain` | 21/21 |
| `answer_refused` | 4/4 |
| `requested_format` | 5/11 |
| `requested_length_kind` | 1/3 |
| `request_quote_verified` | **0/2** |
| `history_quote_verified` | **0/1** |

어긋난 판정이 전부 같은 모양이었다.

```
requested_format  fmt01  기대 'table'          · 실제 'none'
requested_format  fmt02  기대 'numbered_list'  · 실제 'none'
requested_format  req04  기대 'prose'          · 실제 'none'
```

관측을 직접 모아 보니 원인이 나왔다. **모델은 값을 맞게 냈다.** `requested_format` 은
`table` 이었고, `requested_quote` 만 비어 있었다 — 145건에서 27건 중 27건이 빈칸이었다.

`request_quote` 는 그 인용을 이전 질문들과 대조해서, 떨어지면 요구를 없던 것으로
되돌린다. 규칙이 **"인용을 못 대면 요구가 없었다"** 를 전제하는데, 약한 모델은 베끼는
일 자체를 안 하므로 전제가 깨진다. 그러면 규칙이 지어낸 요구가 아니라 맞는 요구를 지운다.

Haiku 에서는 안 보이던 결함이다. Haiku 는 요구가 있으면 인용도 적는다.

## 2. 첫 시도 — 요구를 알아맞히는 탐지기 (버림)

인용을 안 받고 코드가 형식을 **찾아내게** 해봤다. 우리 골든셋 145건에서 16/16 이었다.

그 수치는 의미가 없었다. 양성 표본이 16건뿐이고, 그 16건의 표현을 보고 정규식을 썼다.
외부 데이터(`allganize/IFEval-Ko` 342건)에 돌리니 이렇게 나왔다.

| 필드 | 재현율 | 정밀도 |
|---|---|---|
| format | 97% | **64%** |
| language | **0%** | — |
| length | **20%** | 89% |

- 언어 0% — 정규식이 영어 · 일본어 · 중국어 · 한국어만 안다. 데이터에는 칸나다어 ·
  펀자비어 · 마라티어 · 스와힐리어가 나온다. **언어를 열거로 푸는 것은 원리적으로 안 된다.**
- 형식 정밀도 64% — "큰따옴표로" 를 표 요구로 읽었다. 조사 경계를 안 봐서다.
- 길이 20% — "줄" 과 "자" 만 셌는데 실제로는 단어 · 단락 · 섹션으로 요구한다.

## 3. 채택 — 찾지 않고 확인한다

**후보를 찾는 것과 답을 확인하는 것은 다른 문제다.** 판정자가 `table` 이라고 말한 뒤라면
표 어휘 하나만 보면 된다. 후보를 고를 필요가 없어서 오탐이 날 자리가 훨씬 좁다.

층을 이렇게 가른다.

| | 누가 정하나 | 코드가 확인하는 것 |
|---|---|---|
| 형식 | 판정자 (닫힌 집합 6개) | 그 값의 어휘가 앞 질문에 있는가 |
| 언어 | 판정자 (ISO 코드) | 언어를 지정하는 말이 **있었는가** (어느 언어인지는 안 봄) |
| 길이 | 판정자 (종류 · 값) | 분량을 지정하는 말이 **있었는가** (몇인지는 안 봄) |

원래 막으려던 병은 그대로 막힌다. 후속 발화에서 처음 나온 요구는 이전 질문에 그
어휘가 없다.

`ragdiag/requests.py` 에 있고, `features/request_quote` 가 쓴다. 인용 대조는 남겨서
`request_quote_verified` 로 기록만 한다 — 판정에는 안 쓰지만 어느 모델이 인용을 얼마나
적는지가 다음 판단의 근거가 된다. **셋을 따로 지운다** — 전에는 인용 하나가 떨어지면
언어 · 형식 · 길이를 한꺼번에 없앴는데, 서로 독립된 요구다.

## 4. 검증셋과 테스트셋을 가른다

정규식을 우리 골든셋으로만 재면 그 셋의 표현에 맞춘 것이 100% 를 내고 끝난다.
2절이 그 함정을 실제로 보여줬다. 그래서 셋을 셋으로 나눴다.

| 역할 | 셋 | 크기 | 쓰임 |
|---|---|---|---|
| 개발 | `fixtures/observations` + `fixtures/messy` | 145 | 우리 도메인 · 실데이터 모양 |
| 검증(dev) | `allganize/IFEval-Ko` | 342 | **보면서 패턴을 고쳤다** |
| 테스트(test) | `danish-foundation-models/multi-ifeval` `ko` | 524 | **한 번도 안 봤다** |

테스트셋은 같은 IFEval 원문을 **다른 팀이 따로 번역한 것**이다. 한국어 표현이 독립이라,
우리 정규식이 특정 번역체에 맞춰진 것인지가 드러난다.

두 외부 셋이 서로 다른 구멍을 잡았다는 것도 확인됐다. IFEval-Ko 는 번역체라 언어
이름이 길어("구자라티어") 한 글자 언어명의 결함을 못 잡았고, 우리 골든셋의
"영어로 짧게 답해 주세요" 가 그걸 잡았다. 반대로 띄어쓰기 없는 문장과 조사 경계
문제는 외부 셋에서만 드러났다.

### dev 에서 고친 것들

| 증상 | 원인 | 고친 것 |
|---|---|---|
| "큰따옴표로" 가 표 요구 (오탐 21) | 앞 글자를 안 봄 | 낱말 경계 + 꼬리 낱말 블록리스트 |
| "도와줄 수 있나요" 가 길이 요구 (10) | `단위 + 수` 규칙 | 규칙 삭제 |
| "12개의 자리 표시자" (7) | `자` 가 낱말 머리 | 조사 열거 + 그 밖 한글이면 거절 |
| "여행" 이 길이 요구 (6) | 수사를 문자 클래스로 씀 | 온전한 낱말만 |
| "*로 구분" 이 불릿 (15) | 단락 구분자 · 강조 표시 | 규칙 삭제 |
| "800단어를" 을 놓침 | `(?![가-힣])` 가 조사까지 막음 | 조사 열거로 교체 |
| "영어로" 를 놓침 | 어(語) 앞 두 글자 이상 요구 | 알려진 한 글자 언어명 따로 |
| "테이블을 보여주세요" 가 형식 요구 | 명사 단독 허용 | `테이블로` · `테이블 형식` 만 |

### 최종 수치

| | dev (342) | **test (524)** |
|---|---|---|
| 형식 json — 확인 / 오탐 | 100% / 0.0% | **100% / 0.4%** |
| 형식 bullet — 확인 / 오탐 | 100% / 0.9% | **94% / 1.6%** |
| 형식 table — 오탐 | 0.9% | **1.3%** |
| 형식 numbered — 오탐 | 0.0% | **0.0%** |
| 언어 — 확인 / 오탐 | 100% / 0.3% | 양성 없음 / **10.1%** |
| 길이 — 확인 / 오탐 | 89% / 1.9% | **87% / 7.2%** |

형식은 번역체가 달라져도 버틴다. 길이는 재현율은 유지되는데 오탐이 네 배가 된다.

## 5. 남은 것

- **언어 오탐 10.1%** (테스트셋). 검증셋에서 0.3% 였던 것이다. 이 번역본에는
  `language:response_language` 라벨이 아예 없어서 재현율은 못 쟀다.
  `tests/test_requests.py` 에 `xfail(strict=True)` 로 박아 두어 잊지 않게 했다.
  **진단하려면 이 셋을 봐야 하고, 보는 순간 테스트셋이 아니게 된다.** 셋을 하나 더
  구한 뒤 고치는 것이 맞다. 파이프라인에서의 영향은 제한적이다 — 이 함수는 판정자가
  언어 요구를 주장했을 때만 불린다.
- 길이 오탐 7.2% 도 같은 자리다. 한국어 IFEval 변형이 셋 더 있는데
  (`thunder-research-group/SNU_Ko-IFEval`, `davidkim205/ko-ifeval`,
  `global-llm-2024/ko_ifeval`) 전부 게이트가 걸려 있어 토큰이 필요하다.
- `history_quote` 는 아직 인용 대조를 쓴다. 9B 에서 6/23 이다. "앞에서 정한 조건" 은
  형식처럼 닫힌 집합이 아니라 코드로 확인할 방법이 마땅치 않다.
- 실데이터에서 `observation.request_quote_verified` 의 비율을 세면, 사내 모델이 인용을
  적는 모델인지 아닌지가 바로 나온다. 적는 모델이면 대조를 다시 켤 근거가 된다.

# 근거 활용(Step 3 · ⑨) 개선 — 측정과 결정

Step 1 · 2 와 같은 방식이다. 약한 판정 모델(Haiku 4.5 를 대리로) 기준으로 가설을 세우고,
실제 검색 결과 모양(문서 10~15개 × 약 500자)의 골든셋으로 잰 뒤 결정했다. 판정 세 단계 중
마지막이다.

## 읽고 나서 눈에 띈 것

- **입력**: 답변 + 청크 전부. 질문 · 불만 · Step 2 결과는 안 준다. **출력**: `used` / `ignored` /
  `contradicted` 하나. 인용 칸이 없어 ⑧ 같은 코드 대조가 없다.
- **라우팅**: `ignored` → case22, `contradicted` → case18, `used` → answer_actionable 에 따라
  case17 / 13.
- **설계상 사각지대**: 질문을 안 주므로 "답변이 **아무** 청크나 썼는가" 를 묻는 셈이다. 문서에
  기한과 금액이 있고 사용자는 기한을 물었는데 답변이 금액만 말했다면, 답변은 문서를 썼지만
  요구는 무시한 것(case22)이다. 원래 설계는 질문을 감춰 ⑦과의 독립성을 지키려 했다.
- 골든셋 8건 · 청크 한 문장. 6차 흔들림 측정에서 Step 3 뒤집힘 3/71.

## 가설

| # | 가설 | 층 |
|---|---|---|
| H1 | 답변이 **엉뚱한 청크**를 썼을 때 `used` 로 읽는다 (질문을 모르니 관련성을 못 본다) | 설계 |
| H2 | "인사팀에 문의하세요" 류 회피성 안내를 `used` 로 읽는다 | 모델 |
| H3 | `contradicted` 오탐 — 단위 표기 차이("50%" vs "100분의 50"), 신구 규정 중 하나와만 다름 | 모델 |
| H4 | 문서 15개 · 뒤쪽 청크를 답변이 썼을 때 놓치고 `ignored` | 모델 |
| H5 | 문서 일부만 쓰고 나머지는 일반론일 때 used/ignored 경계가 흔들린다 | 정답 애매 |
| H6 | 인용 칸이 없어 근거 없는 판정을 걸러낼 장치가 없다 — 답변 구절 + 문서 구절을 내게 하고 코드로 대조 | 구조 |

## 골든셋 8 → 50건 (`judgments.GROUNDING_WIDE`, g01~g42)

Step 2 의 500자 청크 풀(`public_docs.CHUNKS`)에서 검색 결과처럼 고른다 — 요구에 답하는 청크 +
같은 장 + 같은 법령 + 다른 법령, 10~15개, 위치는 앞 · 중간 · 뒤. 케이스마다 질문과 Step 2 가
인용했을 청크 번호(`cited`)를 둔다(변형 측정용).

| 범주 | 건 | 뜻 |
|---|---|---|
| used_clear · used_multi · used_unit | 6 · 3 · 3 | 표현만 바꿈 · 두 청크 종합 · 단위 표기 다름 |
| ignored_generic · ignored_deflect | 4 · 5 | 일반론 · 회피성 안내 |
| ignored_wrong_chunk (H1) | 5 | 답변이 문서의 **다른** 청크는 썼지만 요구에 답하는 청크는 안 씀 |
| contradicted_number · contradicted_conclusion | 4 · 3 | 숫자 · 결론이 반대 |
| contradicted_trap | 3 | 한 청크와는 다르지만 맞는 청크와는 일치 → used |
| position | 3 | 답변이 쓴 청크가 15개 중 맨 뒤 |
| partial_use | 3 | 일부만 씀 → accept {used, ignored} |

## 네 변형 × Haiku 3회 (캐시 없음 · 4 workers · 회차당 4분)

| 변형 | 입력 | run 1·2·3 | 다수결 | 흔들림 | H1 (15회) |
|---|---|---|---|---|---|
| V0 지금 | 답변 + 청크 전부 | 36·37·36 / 42 | 37 | 5 | 2/15 |
| **V1** | **+ 질문** ("관련 청크를 보는 데만 써라") | **42·42·41** | **42** | **1** | **15/15** |
| V2 | ⑦이 인용한 청크만, 질문 없음 | 40·39·40 | 40 | 5 | 15/15 |
| V3 | V0 + 인용 두 칸(답변 · 문서 구절) 코드 대조 | 37·36·35 | 37 | 5 | 2/15 |

- **H1 은 설계 그대로 드러났다.** V0 은 15회 중 13회를 `used` 로 — "다른 청크들은 질문과 무관하므로
  쓰지 않은 게 적절하다" 는 추론까지 했다. 질문을 주면(V1) 전부 잡히고, 다른 범주는 하나도 나빠지지
  않았다(V0 → V1 다수결이 바뀐 케이스는 H1 넷 + g11 뿐). 두 표의 쏠림을 걱정했던 원래 설계는
  "질문에 잘 답했나를 평가하지 마라, 관련 청크를 보는 데만 써라" 한 줄로 막혔다.
- **V2 는 H1 을 구조로 잡지만 다른 곳이 샌다.** 인용 청크 하나만 주면 답변이 문서를 쓴 케이스를
  `ignored` 로 흘린다(used_clear 15/18, g01 · g05). 문맥 없이 청크 하나와 답변만 보면 표현 차이를
  "안 썼다" 로 읽는 듯하다.
- **V3 의 인용 칸은 H1 에 무력하다.** "썼다" 는 사실 자체는 참이라 인용도 통과한다(답변 구절 114/114 ·
  문서 구절 116/126). 떨어진 10건은 전부 두 청크의 문장을 " / " 로 이어 붙인 것 — ⑧은 한 인용을
  한 청크에서 찾는다. Step 2 에서는 그런 인용이 나온 적이 없어(wide 36건 × 3회 폐기 0) 규칙은 그대로
  두고 한계로만 적는다.
- **H2 · H3 · H4 · H5 는 이 크기에서 드러나지 않았다.** 회피성 안내 15/15 · 함정 9/9 · 뒤쪽 청크
  V1 에서 47/48 · partial_use 9/9(accept). 남는 건 **빠뜨림을 어긋남으로 읽는** 버릇이다 — V0 에서
  "50%" 를 "100분의 50 **이상**" 의 '이상' 을 뺐다고 `contradicted`(g11), 답을 정확히 찾고도 예외
  조항을 안 썼다며 `ignored`(g37). V1 에서는 둘 다 사라졌지만 g39 가 3회 중 1회 `ignored` 라 같은
  버릇이 남아 있다. 프롬프트에 "단서 · 예외를 빠뜨린 건 ignored · contradicted 가 아니다" 를 넣을
  근거는 있으나, 골든셋에 맞춘 예시가 되므로 적용은 따로 정한다.

## 결정 — Step 3 에 `resolved_question` 을 준다 (V1)

`prompts.GROUNDING_SYSTEM` 에 두 문장, `grounding_user_message(case, question)` 에 질문 절.
불만 원문과 ⑦의 verdict · evidence 는 여전히 주지 않는다 — 쏠림을 막는 장치는 그쪽이다.
`process_flow.md` ⑨ 의 "왜 질문을 감추나" 를 "왜 질문을 주나" 로 고쳤고, 스펙 테스트
(`test_spec_compliance` 의 단계별 입력 검사)도 그에 맞췄다.

**messy 라우팅 회귀 (78건 · Step 1 · 2 는 캐시 · Step 3 만 새 호출 17회)** — 75/78. 틀린 셋은
Step 3 와 무관하다: long02 · repeat01 은 2차와 같은 관측 · 충족도 흔들림(캐시라 그대로), rev03 은
Step 1 이 `question_clarity` 를 vague 로 읽어 case1 로 간 것(관측 흔들림). Step 3 를 거친 17건 중
결과가 나빠진 건 없고, 반대 상황 rev01 · rev02 는 case22 로 맞게 간다.

## 남은 것

- 빠뜨림 ≠ 어긋남 프롬프트 제안 (위). 적용하면 g11 · g37 · g39 류가 안정될 것이나 골든셋 과적합
  위험이 있어 실데이터에서 `contradicted` 비율을 본 뒤 정한다.
- 인용 대조는 한 인용을 한 청크에서 찾는다. 두 청크에 걸친 인용을 살리려면 조각마다 청크를 따로
  찾게 해야 하는데, Step 2 에서 그런 인용이 나온 적이 없어 미룬다.
- Step 3 은 이제 판정 세 단계 중 마지막까지 골든셋으로 잰 상태다. 남은 큰 항목은 판정이 아니라
  Step 1 의 (b) 프롬프트 제안 적용 여부, messy 셋 청크의 실제화, 무캐시 3회 회귀 재측정이다.
